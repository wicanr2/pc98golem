# Spec 004：D88 磁碟容器

狀態：READY。

## 為什麼要第二種容器

`internal/vfd` 讀的是 Virtual98／T98 的 `.fdd`。PC-98 版《Pool of Radiance》
（Pony Canyon，1989-12-21）流傳的是 **D88**——另一種容器，Neko Project II 與
多數 PC-98 模擬器的原生格式。兩者裝的都是同一種 2HD 軟碟，但版面完全不同：
VFD 是「一張大磁區表 + 資料區」，D88 是「軌表 + 每軌自帶磁區標頭」。

## 版面（由手上兩份映像量出來）

量測腳本 `workplace/probe/d88_survey.py`，對象是
`Pool of Radiance (Disk A/B).d88`（各 1281968 位元組）。

```
$0000  名稱，17 位元組，NUL 結尾（兩份都是 "New FD Image"）
$0011  保留 9 位元組
$001A  防寫旗標（$00 = 可寫）
$001B  磁碟類型（$20 = 2HD）
$001C  磁碟總長度，小端 32 位元（= 檔案長度）
$0020  軌表：164 筆小端 32 位元偏移，0 代表這一軌沒有資料
$02B0  第一軌的資料
```

每一軌是連續的磁區，每個磁區前面有 16 位元組標頭：

```
+0  C   磁柱
+1  H   磁頭
+2  R   磁區號（1 起）
+3  N   大小碼
+4  這一軌的磁區數，小端 16 位元（**每個磁區都重複一次**）
+6  density
+7  deleted mark
+8  status（$00 = 讀得到）
+9  保留 5 位元組
+14 這個磁區的資料長度，小端 16 位元
+16 資料
```

**下一個磁區的位置要用 `+14` 的資料長度算，不能用 `128 << N`。**
兩者在正常映像上相同，但保護軌會故意讓它們不一致；用 N 推位置會在
那一軌之後整個錯開，而且錯開的方式看起來像「檔案內容怪怪的」。

### 軌索引

`軌索引 = C * 2 + H`。兩份映像 154 條軌全部成立，沒有例外。
LBA 照 VFD 那一層同一條式子：`LBA = (C * 2 + H) * 每軌磁區數 + R - 1`。

## 手上這兩份的實際形狀（confirmed）

| 項目 | Disk A | Disk B |
|---|---|---|
| 有資料的軌 | 154（77 磁柱 × 2 面）| 154 |
| 每軌磁區 | 8，R = 1..8 | 8，R = 1..8 |
| N／資料長度 | 3／1024，全部一致 | 3／1024 |
| status | 全部 `$00` | 全部 `$00` |
| 軌表的洞 | 無 | 無 |
| 形狀不同的軌 | 無 | 無 |

Disk A 的檔名帶 `[T4,7,115,149]`（Wizardry V 型防拷所在的軌）。
**那是 flux 層（SCP／MFI）的資訊，D88 這一層沒有留下任何痕跡**——
那四軌的磁區數、大小、status 與其他 150 軌完全相同。所以：

- 讀檔案不會踩到壞磁區，[fat.Volume] 不會回 `ErrAbsent`。
- 但**不能因此說「這片沒有防拷」**。要驗防拷得回頭看 SCP，那不在本規格範圍。

## 開機磁區

Disk A 的 sector 0 有合法 BPB（`FromBootSector`，不是假設）：

```
e9 0d 01                 jmp
"SPS PC98"               OEM
每磁區 1024   每叢集 1   保留 1   FAT 2 份
根目錄 192 項  總磁區 1232  media $FE  每 FAT 2 磁區
每軌 8        磁頭 2      隱藏 0
```

1232 × 1024 = 1261568，PC-98 2HD 的標準容量。

## 契約

1. `d88.Open`／`d88.Parse` 產出的型別滿足 `disk.Image`（`Sector`／`SectorSize`／
   `Count`／`Absent`），`fat.Mount` 兩種容器都吃。
2. 磁區位置由**逐軌走訪**建立，不假設磁區在檔案裡按 LBA 排序，
   也不假設每軌磁區數相同——同一份映像的不同軌可以不一樣。
3. `status != $00` 的磁區記成讀不到（`Absent`），[fat] 那一層照 spec 002 §4
   的規矩吵出來，不補零。
4. 磁區表為空、軌表偏移越界、磁區標頭越界一律開檔失敗，不做部分解析。
5. 每軌磁區數取**第一個磁區標頭**的 `+4`；後續磁區的同一欄位不一致時以第一個
   為準，並且不因此失敗（保護軌會這樣）。

## 驗收

不需要 CPU、不需要跑遊戲：

- 兩份映像各讀得到 1232 個磁區、0 個 absent。
- `fat.Mount` 的 `Geometry` 是 `FromBootSector`。
- 根目錄列得出檔案，且每個檔案的開頭是它該有的樣子
  （`MZ`、`TPOV`…，照 spec 002 §3 的判準）。
- 原版映像不進版控；缺檔就 skip。
